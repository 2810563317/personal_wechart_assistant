## 代码注释规范（必须遵守）

这是一个学习型项目。

生成代码时，必须添加必要且有价值的注释，帮助理解代码设计，而不是简单解释 Python 语法。

注释原则：

1. 解释"为什么这么设计"，而不是解释"这一行代码在干什么"。

例如：

✅ 好的注释：

# ChatService 负责聊天流程编排，不关心具体使用哪个模型。
# 后续会在这里加入 Memory、Tool、Prompt 等能力。

❌ 不好的注释：

# 调用 model_service.chat()

--------------------------------------------------

2. 每个类（Class）必须有类注释。

说明：

- 这个类负责什么
- 为什么存在
- 不负责什么

例如：

class ChatService:
    """
    聊天业务编排层。

    职责：
    - 接收用户消息
    - 编排聊天流程
    - 调用 PromptService、MemoryService、ModelService

    不负责：
    - HTTP 请求
    - DeepSeek API 调用
    """

--------------------------------------------------

3. 每个公共方法必须有方法注释。

包括：

- 参数说明
- 返回值
- 方法职责

例如：

async def chat(message: str) -> str:
    """
    执行一次聊天流程。

    Args:
        message: 用户输入

    Returns:
        AI 回复内容

    """

--------------------------------------------------

4. 复杂业务逻辑前必须有流程注释。

例如：

# ① 获取最近聊天记录
# ② 生成 Prompt
# ③ 调用模型
# ④ 保存聊天记录

--------------------------------------------------

5. 不允许出现大量无意义注释。

例如：

# 定义变量
x = 1

# 调用函数
foo()

这类注释禁止出现。

--------------------------------------------------

6. 如果某个设计体现了软件架构思想，请额外说明。

例如：

# ChatService 依赖 ModelService，而不是 DeepSeekProvider，
# 这样以后切换 OpenAI/Qwen 时，业务层无需修改。

--------------------------------------------------

7. 当新增模块时，必须在文件顶部增加模块说明。

例如：

"""
PromptService

负责统一构建发送给大模型的 Prompt。

后续会逐步加入：

- Memory
- MCP Tool
- RAG
- System Prompt

当前版本仅负责：
System Prompt + User Message
"""
